# Review Phase Contract

Input is a fixed-baseline `change-set`, approved Spec/Task Plan, repository revisions, language/project rules, and impact evidence. Output is a `review` envelope with independent Standards and Spec axes; each finding has severity, path/symbol, revision, evidence, acceptance criterion, and `CONFIRMED`, `REJECTED_WITH_REASON`, or `NEEDS_CLARIFICATION` classification. The Review result carries no approval and cannot submit code. Persist it to KU and comment iCafe through the parent. A dual-axis `PASS` is only a prerequisite for the parent-owned G7 iCode-submission approval, which must bind the exact reviewed Change Set hash and matching input/revision hashes. Stop or route to the parent on provider `INCOMPLETE`, any `NEEDS_CLARIFICATION`, stale or hash-mismatched baseline/input, missing Spec/Plan, or blocking `CONFIRMED` finding; blocking findings go to `tom-diagnose`, while non-blocking/non-PASS results cannot reach G7. Review source only, never compile or run tests locally.
