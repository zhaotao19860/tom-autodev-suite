# 审批与进度通知示例

以下是消息结构示例，不是已发送的审批，不代表 BGW-1995 已进入 G5/G9。尖括号部分由运行中的真实证据填充；不会把占位路径当成可点击链接。渲染回归见 `tom-autodev/scripts/tests/test_approval_materials.py`。

## G0：启动绑定

> tom-autodev G0 审批
>
> 本次审批：需求、项目、协作与路由绑定
>
> 审批重点：核对需求范围与验收、项目和仓库分支、群名/成员/角色，以及 change_class 与阶段模式。
>
> 请先查看这些文件 / 证据：
>
> - 本次审批全文：`<本机 artifacts 下的 approval-material/content.bin 实际路径>`，JSON 文本，包含需求快照和本次选择。
> - 项目配置：`<需求级 profile 实际路径>`，同时给出固定 profile hash。
> - 每个业务仓/独立测试仓的实际目录、分支；已有固定 revision 时显示该值。
> - 已配置的知识库需求文档。
>
> 批准后：确认本次绑定，控制器随后建群并进入 GRILL，不授权提交代码或发布。
>
> [同意] [驳回]

没有协作群时，详情和按钮发送到审批成员的机器人单聊。

## G5：完整候选改动

> tom-autodev G5 审批
>
> 本次审批：当前任务的候选 Change Set
>
> 审批重点：业务和独立测试完整 diff、基线/候选版本、验收追溯、每项计划偏离；不能只看摘要。
>
> 请先查看这些文件 / 证据：
>
> - 本次审批全文：`<从匹配 hash 的已保存草案导出的材料实际路径>`。
> - 全文中的 `draft.business_patch`、`draft.test_patch`、`full_diff_hash`、`deviations` 与版本。
> - 草案明确提供的源文件/证据路径。
>
> 决定边界：只授权本次 input_hash 对应候选；不等于批准后续 iCode 提交。
>
> [同意] [驳回]

若草案与本次审批 hash 不匹配，详情明确显示“材料缺口：未取得与本次 hash 匹配的产物，请勿批准”。

## G9：发布核验

> tom-autodev G9 审批
>
> 本次审批：本次发布动作与固定证据
>
> 审批重点：全部必需模块的 build、版本、环境、发布规则和证据一致；旧 build 不可替代。
>
> 请先查看这些文件 / 证据：
>
> - 本次动作的只读材料副本。
> - 当前 action 明确引用的各模块 iPipe 产物实际路径与 build ID。
> - 冻结计划及其引用；各模块版本、环境身份、发布规则。
>
> 批准后：只读核验平台发布；全部必需模块证据通过才记录 RELEASE_SUCCESS，平台未发布则等待，不强制发布。
>
