# 如流群聊取证（可选）

来源：tom-autodebug 1.5.0 SKILL.md 第 5.1 节，2026-11-04 并入 tom-diagnose。

## 何时启用

用户提供如流群号、群聊链接，或明确要求结合群聊上下文排障时，在远程取证前后增加群聊消息采集。群聊消息是辅助证据，用于恢复故障时间线、业务现象、已做操作和待办；它不能替代远端命令、日志、抓包或代码验证。没有启用群聊取证时，不要为了凑流程调用 InfoFlow。

## 读取方式

先加载并遵循 `infoflow-cli-shared` 和 `infoflow-cli-im` 的环境自检、凭据和错误处理规则。执行任何 InfoFlow 命令前，按 `infoflow-cli-im/references/environment-setup.md` 完成环境检查；同一会话已完成检查时不重复执行。

默认读取最近 24 小时，优先使用纯文本 transcript，便于和远端证据按时间线对齐：

```bash
infoflow-cli im message get-group-messages \
  --group-id <group-id> \
  --start-time -24h \
  --end-time now \
  --transcript-only
```

用户给出明确时间范围时使用用户范围；超过 24 小时时按连续时间窗口分段读取，不得直接传入超过 24 小时的范围。需要保留消息 ID、回复关系或结构化字段时，改用 `--include-items`，并始终把消息 ID 当字符串处理，避免大整数精度丢失。

## 取证顺序

1. 记录群号、查询时间范围和命令结果；消息为空时说明查询范围内没有可用消息。
2. 从消息中提取故障开始时间、现象、影响范围、拓扑/配置、已做变更、明确的待办和关键参与人。
3. 将群聊陈述标记为“群聊观察”，将远端命令输出标记为“现场证据”；只有两者相互印证时才把结论写成已确认根因。
4. 用消息时间和远端 `date -Ins` 对齐时间线；发现时钟偏差时在报告中注明。
5. 把群里尚未验证的猜测列入“待验证项”，不要直接当作根因或执行依据。

## 失败降级

- `bot_not_in_group`、`bizcode_720003` 或“机器人未在群成员列表中”：停止群聊读取，提示用户把当前配置的机器人加入群；不得自动追加 `--confirm` 执行加群。
- `bizcode_720001`：机器人已在群内但未获得历史消息权限，提示群主在群设置中授权读取历史消息。
- 凭据、网络或 Ugate 鉴权失败：按对应 InfoFlow Skill 的恢复流程处理；如果无法恢复，继续远程排障，并在报告中写明群聊证据不可用。
- 群聊读取失败不应使已经成功获取的远程证据失效，也不能为了补群消息而重复执行有副作用的远程命令。

## 报告

最终报告至少包含“群聊时间线/观察”“现场证据”“交叉验证结论”“未验证假设”“处理建议”五部分。workflow 诊断中，群聊内容只能写进 `log_evidence`/`comparison` 等字段并标注为群聊观察，不能替代 iPipe 执行回执。
